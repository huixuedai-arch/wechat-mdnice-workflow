# 公众号排版与预览

## 配置与授权
读取本机 ~/.config/wechat-editorial/profile.json。首次缺失时一次询问文章作者、原创作者（默认同文章作者）、预览接收微信号、输出目录。原创默认设置为文字原创，但先由使用者确认将此设置用于其原创文章；转载或权属不明确时单独核对，不能替其虚构权属。
使用 scripts/profile.py 创建本地配置；不把实际配置、稿件或账户信息提交到 Git。名称、接收人不得写死在代码。开发者也可用命令行参数配置。
配置不是无限发送授权。用户要求完整预览流程时可发送至指定接收人；只改作者、只核对时不发送。既有同篇授权不重复询问。账号或收件人变更时核对具体目标。

## 执行
1. 定位主稿和已有 workflow-state.json。新文章按标题建目录；同篇更新保留文章 ID、MDnice outId 和草稿 ID。显示简短配置摘要。
2. 在 MDnice 创建或更新同篇文档；独立标题、正文、小标题和图片分别核对。使用所选主题，刷新读回；不得以自行生成的近似 CSS 冒称经过 MDnice。
3. 获取 MDnice 实际富文本并记录来源、主题、正文哈希及图片映射。验证实际可用图片，不固定数量，不发布本地路径图片。
4. 通过被允许的浏览器工具或使用者自行运行的适配插件导入公众号编辑页。工具明确拒绝访问时不通过 CDP、私有接口或其他路径绕过。没有可用执行器时明确说明，Skill 不能自动提供浏览器权限。
5. 填标题下作者。按配置选择文字原创，填写原创作者并核对协议及选项；不顺便变更白名单、转载权限、赞赏或推荐设置。
6. 核对标题、正文、排版、摘要、封面、图片和两个作者。保存前备份。监听新保存反馈和新增历史记录，取得稳定草稿 ID，刷新读回。时间过短的诊断可能仍处于处理中。
7. 保存核验后进入预览。若默认扫码模式，切换到“通过公众号列表预览”，重新定位可能重建的弹窗。填配置接收人，读回核对，先持久化 preview-pending 再点击一次发送。成功反馈记录为 preview-sent；用户收件确认记录为 recipient-confirmed。结果不明记录 preview-unknown，不重试。
8. 停在预览完成，永不点击发表、群发或自动发布接口。

## 局部修改与恢复
仅改作者及原创时，先保存当前正文快照，不要求与旧稿包相同；保留使用者新编辑。更新设置并保存后核对正文未变化，不发预览。只读核对不写值、不点保存，打开原创窗口后读取状态并取消退出。
按文章 ID + 公众号标识 + 稿件版本记录执行状态，不仅使用标签页 ID。刷新、换标签或重装后的记录缺失不能解释为未发送。发送结果不明先查证。
区分文本/图片/结构的变化与编辑器属性及 CSS 序列化差异；记录具体不同字段，不能直接跳过核验。等待编辑器数据加载完成，不只等待外壳出现。
