# 微信公众号文章与贴图流程

## 配置与交付目录
读取本机 `~/.config/wechat-editorial/profile.json`。首次缺失时合并询问公众号标识、文章作者、原创作者（默认同文章作者）、预览微信号和输出根目录；用 `scripts/profile.py` 保存。配置只存本机，不提交 Git。原创仅用于符合声明条件的稿件，不能虚构权属。

每篇素材保存为 `<输出根目录>/<文章标题>/`，正文、原图、文章包和使用说明放在一起，不再使用“测试”目录。标题含路径分隔符时替换为安全字符；目标目录已存在时先核对，不覆盖其他文章。改标题可重命名同篇目录，但保持稳定 articleId、MDnice outId 和草稿 ID。更新稿件前保留旧版；运行记录不作为公共示例上传。

文章作者/素材 Agent 负责交付可加载的 JSON 包，使用者无需手改 JSON。标题、正文或图片更新后，沿用 articleId 重新打包，再在插件中清空旧包并导入新包。写作风格服从用户要求，不强制套用模板。

## 按内容类型执行
- **普通文章**：经过真实 MDnice 排版、保存并读回；获取实际 HTML、主题和图片映射，用 `scripts/build_package.py` 打包。不能以近似 CSS 冒称 MDnice 输出。插件“文章”tab 对应公众号“文章”编辑页，导入、设置两个作者及文字原创、保存刷新核对，再按授权发送预览。
- **贴图**：读 [贴图素材与运行规则](references/image-text.md)。原始图片按顺序上传，标题和正文为纯文本，不走 MDnice。插件“贴图”tab 对应公众号“贴图”编辑页。逐字保留空格、空行，首图为封面。

插件主界面：打开公众号后台 → 本机设置 → 导入文章包 → 核对稿件及图片 → 主按钮执行。没有 MDnice 直接导出入口。技能本身不提供浏览器权限；使用允许的浏览器工具或用户自行运行的插件，工具拒绝的网站访问不得绕过。

## 保存、预览与结束条件
保存反馈不能单靠等待时间判断：取得草稿 ID，刷新后核对标题、正文和图片顺序。保存错误记录原文，结果未知先核对，不重复上传或盲目重试。

普通微信号预览：默认扫码但仍有“通过公众号列表预览”选项时，切换并核对指定收件人；发送前持久化 `preview-pending`，只点击一次。成功反馈为 `preview-sent`，用户确认收件才是 `recipient-confirmed`；结果不明为 `preview-unknown`，不自动重发。

**贴图只提供扫码预览时**：必须已保存、刷新读回一致，再以 `draft-ready` 结束，通知“草稿已保存并核对，请到草稿箱审核并发表”。不要求用户扫码来完成自动化，不标记预览已发送，不因二维码出现就断言微信全平台取消微信号预览。已有核验成功的草稿无需重复点击保存。

最终发表始终由用户手工完成，不点击发表、群发或调用公开发布接口。只改署名、只读核对或仅准备包时不发送。既有同篇、同收件人授权沿用；不能把配置当作无限发送授权。

## 恢复与报告
按公众号、文章 ID、版本及当前草稿身份定位运行记录；不能用另一标签页的历史状态盖过当前稿件。已保存草稿从核对继续，保留已上传图片。空白新页仍走新建；已有内容只有唯一匹配同篇记录后才恢复，未知修改不覆盖。清空包不清除设置、网页内容、任务及防重发记录。

运行中允许只读采集诊断；诊断可能包含标题、作者、收件人和草稿 ID，不公开上传。报告区分素材已准备、草稿已核验、预览已发送和用户已收到；模拟测试与真实站点验证分开。交互细节见 [references/interaction.md](references/interaction.md)。

## 已发表贴图修改
用户明确要求修改已发表贴图时，使用插件的独立“修改已发表贴图”入口，先列出新旧差异并备份当前内容，再通过页面允许的控件填入。不得套用新稿/草稿恢复逻辑；图片数量保持不变，平台限制以当前页面为准。填入核对后停在 `published-ready`，提交修改由用户手动完成；此状态不代表已保存或线上内容已更新。详细步骤见 references/image-text.md。
