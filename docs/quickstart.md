# 安装与操作（1.9.5）

## 一次安装
从 [最新版本](https://github.com/huixuedai-arch/wechat-mdnice-workflow/releases/latest) 下载 ZIP，解压到固定目录。Chrome 打开 `chrome://extensions`，开启开发者模式，加载包含 `manifest.json` 的文件夹。升级覆盖同一目录并点重新加载，不卸载，以保留本机设置与防重发记录。

打开插件“本机设置”，填写公众号标识、文章作者、原创作者、预览微信号。署名由每位使用者自己配置。原创仅用于符合条件的稿件。

## 每篇操作
1. [打开公众号后台](https://mp.weixin.qq.com/)，登录。普通文章新建“文章”，多图纯文本新建“贴图”，停留在空白编辑页；恢复同篇则打开已保存草稿。
2. 从工具栏打开插件，选对应 tab，导入素材 Agent 提供的 JSON 包。还没有包时用“获取 Agent 指令”，提供稿件、风格、素材和输出根目录。
3. 核对标题、正文字符数和图片数量。文章可选正文图片作封面；贴图按图片顺序上传，第一张为封面。
4. 点击底部主按钮，保持页面打开，等待保存和刷新核对。
5. 微信号预览可用时发送一次；贴图仅有扫码预览时，状态为“草稿已保存并核对”，到草稿箱审核并手工发表。无需扫码来完成流程。

素材统一放在 `<输出根目录>/<文章标题>/`。贴图格式和打包命令见 [贴图说明](image-text.md)；普通文章必须先经过真实 MDnice 排版，格式见 [文章包协议](article-package.md)。插件不再提供 MDnice 导出入口。

修改标题/正文/图片后让素材 Agent 重新生成 JSON，保持同篇 articleId。插件“清空”再导入新包；清空不删除设置、草稿、任务或发送记录。

遇到停止：先保留编辑页面，在“遇到问题？”下载完整诊断。运行中也可只读采集，不重新上传，不用反复点击来确认是否送达。诊断可能含私人标题、接收人及草稿 ID，不公开上传。保存核验、发送成功和用户收件是不同结果。

## 已发表贴图修改（1.10.0）

这与草稿替换不同。在公众号打开已发表内容的“修改”页面，插件选择贴图 tab、导入新包，勾选“修改已发表贴图”。点“核对已发表文章的新旧内容”，检查新旧文字及图片，之后点“按上述差异填入，提交由我完成”。

插件备份页面原文和原图地址，仅通过页面已有换图控件替换图片，核对文字和图片顺序后停为 published-ready。不会保存、预览或提交修改；使用者在公众号页面审核并手动提交，修改次数与字段限制以平台当前页面为准。不要把本地填入成功当作线上文章已更新。

本版保持图片数量不变。原图校验记录可用时仅替换变化的图片；记录不足时展示全部新旧图片，须核对后才执行。未找到唯一换图入口、字段只读、页面在核对后变化、平台未完成上传时停止并保留诊断，不删除原图以绕过限制。本功能通过隔离浏览器模拟测试，尚未在用户的已发表页面实测。
